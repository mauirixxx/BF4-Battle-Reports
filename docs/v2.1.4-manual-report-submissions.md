# BF4BR v2.1.4 — Manual report submissions (staged)

Status: **in development; NOT enabled in production**.

## Design

The archive homepage has a disabled placeholder for Battlelog URL submission. The public `website/manual-report-gateway.php` is modeled on BF4PS's existing manual and platoon gateways: HTTPS, same-origin and session CSRF, URL validation, per-IP limit (10/hour), and forwarding to a loopback-only endpoint. Its limiter directory `/var/lib/bf4br-manual/limits` must be created writable by the PHP user before enabling.

The private FastAPI app `bf4br.manual_report_api:app` is designed to bind to **127.0.0.1:8794 only**. Its dedicated `BF4BR_MANUAL_DSN` must use a least-privilege database role. Never expose this endpoint publicly. Do not start it until migration and integration tests pass.

`bf4br.manual_report.submit` distinguishes complete reports (no work), archived incomplete reports (priority detail enrichment), and missing reports (priority generic collection). The URL's trailing persona is only a hint and does not create a roster association. The report worker's existing import flow remains authoritative.

`migrations/0010_manual_report_priority.sql` introduces two priority flags and a deduplicated submission ledger. Generic queue claims, detail activation, and player claims prioritize manual requests. Detail seeding carries the flag forward from the ledger, including when a generic report was submitted before import.

## Release gates

1. Reconcile both collector checkouts and existing uncommitted changes before deployment.
2. Run migration on an isolated PostgreSQL database, test archived-incomplete, complete, missing, repeated, and concurrent submissions, then run queue integration tests.
3. Verify the new API and gateway with a least-privilege database role, loopback binding, correct TLS/Cloudflare reverse proxy behavior, and rate limits.
4. Verify an archived incomplete report is selected ahead of routine enrichment without overriding active leases, cooldowns, or retry constraints.
5. Deploy migration and compatible worker changes across the fleet, enable gateway and homepage form, then verify and tag v2.1.4.

The existing PHP homepage backup on the reports host is `/var/www/html/battle-reports.php.pre-v214-placeholder-20261116`.
