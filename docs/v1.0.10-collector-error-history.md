# BF4BR v1.0.10 — durable collector error attribution

## Changes

- Additive migration `migrations/0005_collector_error_history.sql` creates append-only `bf4br_collector_error_history`, with timestamp, node, worker, job kind, platform, item ID, optional UTC day and error message. Existing queue rows and fetch logs remain unchanged.
- Historical and daily queue release functions record errors in the same transaction as the lease-token-fenced release. The previous lease owner is captured under row lock before clearing it. Stale or expired releases do not create events.
- The live monitor includes a permanent error-history feed while retaining existing legacy internal-error and report-fetch feeds. Newly recorded errors retain node attribution after a job is released.
- Existing entries whose lease owner was previously cleared remain unattributed unless other reliable records establish the origin.

## Deployment

1. Apply migration 0005 to the database before deploying updated workers (already applied to production on November 4, 2026).
2. Verify the monitor JSON endpoint remains healthy (HTTP 200 verified on `/var/www/html/battle-reports-live.php`).
3. Release updated collectors through the normal rolling updater.
4. Verify newly recorded error rows contain node and worker IDs, and confirm the monitor displays them after leases clear.

## Tests

- Isolated PostgreSQL integration test covers historical persona, daily persona, report errors, cleared lease owner, and stale-token duplicate suppression.
- Existing queue integration suite passed (4 tests).

This release does not alter request pacing, assignments, or concurrency.
