# v1.0.3 platform fairness and fresh-first report selection

The database-host feeder maintains separate persona and report queue targets for platforms 1 (PC), 32 (PlayStation), and 64 (Xbox), rather than allowing PC to saturate a shared global threshold. Existing queued work remains intact.

Each node supervisor assigns platform preferences to spawned workers. With the standard four-node fleet (three persona workers and one report worker per node), each node has one persona worker for each platform. The first three report nodes prefer PC, PlayStation, and Xbox respectively; the fourth is flexible. A platform-specific worker never claims work from another platform. When a platform has no ready jobs, its worker waits; this deliberately prioritizes fairness over maximum utilization.

Within a platform, report claims prefer newest known history_discoveries.report_timestamp, then next_attempt_at. Leases, fencing, retries and cooldowns remain unchanged. This prioritizes discovered current-day reports, not reports not yet discovered.

Caveats: platform assignment is fixed at child spawn and only recalculated on restart/resize; custom node sizes or changing node membership may cause imperfect splits. Fresh persona head scans independent of deep backfill are not yet implemented. No database migration is required for this release.
