# BF4BR v1.0.5 — daily UTC catch-up

Status: implementation in progress; **not enabled in production**.

At midnight UTC, schedule the preceding UTC day `[start, end)` for a dedicated three-node pool. Other nodes continue their historical queues. The dedicated pool must have separate persona-discovery cursors and report claims; it must not overwrite `bf4br_persona_jobs.cursor_epoch`, `boundary_epoch`, or other historical state.

## Verified discovery input

BF4SW `bf4_player_sessions` (model and Alembic migration 0008) records platform, nullable `persona_id`, `player_name`, `time_joined`, `last_seen`, and nullable `time_left`. A session overlaps the day when `time_joined < end` and `COALESCE(time_left,last_seen) >= start`. Map BF4SW PC, PS4/5, XBox to Battlelog 1, 32, 64. Missing persona IDs are counted separately, not guessed from names. This source covers observed BF4SW servers, not all possible Battlefield matches.

## Work scheduling

1. Import distinct observed `(platform,persona_id)` identities into a **separate** day-scoped queue with a durable checkpoint and lease fencing.
2. Fetch each identity's latest Battlelog history using a fresh cursor, stopping after crossing the start of the target day; handle pagination and API errors with bounded retries.
3. Deduplicate `(platform,battlelog_report_id)` against existing report discoveries, but use a separate daily-priority report claim lane so the backlog queue remains intact.
4. Assign exactly three designated nodes, preferably one per platform, to priority persona and report work. Keep the fleet's current **one persona worker per node** safety limit until BF4PS load is validated.
5. Recheck previous-day discovery for late-arriving reports, record unresolved failures, and publish coverage counters.

## Release gates

- Verify read-only BF4SW connection and actual production session distribution, including null persona IDs.
- Design and review additive BF4BR migration and indexes using the existing `migrations/0001_worker_queues.sql` and production catalog.
- Test UTC boundary crossing, idempotency, duplicates, late arrivals, lease takeover, worker crashes, platform isolation and query performance.
- Canary a single node without altering historical cursors, then expand to three nodes. No automatic activation before these checks.
